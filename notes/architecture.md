# 아키텍처

## 프로젝트 구조

- `src/config`: Phaser와 게임 전역 설정
- `src/scenes`: Phaser Scene
- `src/entities`: 게임 오브젝트와 엔티티
- `src/states`: 상태 머신과 상태 정의
- `src/systems`: 입력, 물리 보조, 기록 같은 시스템 로직
- `src/ui`: Phaser 내부 HUD와 UI
- `src/utils`: 테스트 가능한 순수 유틸리티
- `public/assets`: 정적 에셋
- `tests`: Vitest 테스트

## Scene 구조

현재 Scene 구조는 다음과 같다.

- `BootScene`: 초기 진입용 Scene이다. 현재는 바로 `GameScene`으로 전환한다.
- `GameScene`: 실제 플레이 공간과 플레이어를 생성하고 업데이트한다.
- `PlayableCaseScene`: 특정 기믹 패턴을 메인 수직 맵까지 이동하지 않고 바로 플레이할 수 있는 검증용 Scene이다.

수직 레벨 확장은 `BootScene`이 아니라 `GameScene`과 플레이필드 시스템을 기준으로 진행한다. 후속 작업에서 시작 화면, 결과 Scene 등을 추가로 분리한다.

`BootScene`은 URL 쿼리의 `case` 값이 있으면 `PlayableCaseScene`을 실행하고, 없으면 `GameScene`을 실행한다.

## 플레이어와 플레이필드

- `src/entities/SnailPlayer.ts`: 임시 달팽이 플레이어, 일반 상태와 껍질 상태 전환, 이동, 접면 부착, 껍질 점프, 임시 시각 표시를 담당한다.
- `src/systems/SnailInputController.ts`: 방향 입력, 점프 입력, 상태 전환 입력을 읽어 플레이어가 사용할 수 있는 단순 값으로 변환한다.
- `src/systems/TemporaryPlayfield.ts`: 임시 플레이 공간, 바닥과 좌우 벽, 임시 구조물 생성, 시작 위치, 접면 후보와 지지면 판정을 담당한다.
- `src/systems/TemporaryLevelDefinitions.ts`: 메인 수직 레벨과 기믹 케이스 레벨의 임시 데이터, 필드/발판/경사면 같은 기초 기믹 오브젝트 정의를 담당한다.

현재 플레이어와 플레이필드는 MVP 조작 검증을 위한 임시 구현이다. 최종 그래픽, 최종 물리 수치, 최종 레벨 구조는 아직 확정하지 않는다.

### 임시 플레이필드 구성

현재 필드는 `TemporaryLevelDefinition` 안의 `objects` 목록을 기준으로 코드에서 직접 생성한다. 이 구성은 일반 상태의 접면 부착, 벽타기, 껍질 상태의 경사면 이동, 점프, 카메라 확장 가능성을 확인하기 위한 임시 형태다.

현재 임시 필드 요소는 다음 기준으로 구성한다.

- `field`: 화면보다 위쪽으로 확장 가능한 수직 플레이 공간, 좌우 벽, 하단 바닥을 포함한다.
- `platform`: 수평 발판이다.
- `slope`: 경사 발판이다.

`platform`과 `slope`는 얇은 발판 형태와 하단까지 채워진 솔리드 블록 형태를 모두 가질 수 있다. 하단 채움 형태는 기초 필드, 큰 사각형 지형, 경사 지형을 빠르게 검증하기 위한 임시 표현이다.

하단 채움 형태는 흰색으로 채워진 영역 전체를 실제 충돌 영역으로 다룬다. 윗면의 접면 판정은 얇은 발판과 같은 기준을 사용하지만, 채워진 내부 영역은 달팽이가 들어갈 수 없는 정적 지형이다.

Scene은 기믹 필드이고, 기믹 필드는 여러 오브젝트로 구성된다. 오브젝트 하나가 추적 가능한 최소 단위의 기믹이다.

후속 레벨 작업에서는 이 임시 필드 요소를 그대로 확장하지 않는다. 필드 요소는 최소한 다음 단위로 분리한다.

- 경계 요소: 바닥, 좌우 벽, 천장 또는 낙하 제한선
- 정적 발판: 수평 발판, 경사 발판, 벽 부착 발판
- 기믹 요소: 스프링, 범퍼, 가속 발판, 위험 지형
- 시작점과 목표 지점
- 체크포인트와 카메라 구간

최종 레벨 구조는 Tiled Map Editor 또는 별도 레벨 데이터 로더를 기준으로 관리한다. `TemporaryPlayfield`는 조작 프로토타입 검증용 시스템으로 유지하고, 실제 레벨 제작 단계에서는 `LevelLoader`, `LevelGeometry`, `SurfaceResolver` 같은 역할로 분리한다.

### 기믹 케이스 레벨

기믹은 처음부터 메인 수직 맵 상단에 직접 붙이지 않는다. 먼저 `TemporaryLevelDefinitions.ts`에 작은 케이스 레벨로 정의하고 `PlayableCaseScene`에서 해당 구간만 플레이한다.

개발 흐름은 다음과 같다.

1. `notes/gimmick-cases.md`에 케이스 목표와 상태를 등록한다.
2. 특정 기믹 또는 구조물 패턴을 케이스 레벨로 만든다.
3. `/?case=케이스키` 주소로 해당 케이스를 바로 실행해 조작감을 검증한다.
4. 검증된 플랫폼과 기믹 배치를 메인 수직 레벨 상단 구간에 붙인다.
5. 메인 레벨에서 카메라 이동, 이전 구간과의 연결, 낙하 리스크를 다시 확인한다.
6. `notes/gimmick-cases.md`의 검증 상태와 메인 맵 반영 상태를 갱신한다.

현재 기본 케이스 키는 `slope-transfer`다.

### 접면 판정

일반 상태는 구조물의 위, 아래, 옆면에 붙어 접면을 따라 이동할 수 있다. 접면 판정은 오브젝트 타입이 아니라 `SurfaceEdge`, `AttachmentSurface`, `AttachmentProbe`를 기준으로 처리한다.

`field`, `platform`, `slope`, `solid-to-bottom` 같은 오브젝트 타입은 접면 생성의 원천 데이터일 뿐이다. `TemporaryPlayfield`는 모든 오브젝트를 동일한 `SurfaceEdge` 목록으로 변환하고, 달팽이 일반 모드는 이 edge의 법선, 접선, 진행도만 보고 이동한다.

- `SurfaceEdge`: 실제 달팽이가 붙을 수 있는 선분이다. 시작점, 끝점, 법선을 가진다.
- `AttachmentSurface`: 접면의 법선, 접선, 스냅 위치를 표현한다.
- `AttachmentProbe`: 달팽이의 접면 방향 길이와 접면 수직 깊이를 분리해 판정한다.

일반 모드의 접면 선택 순서는 다음과 같다.

1. 달팽이의 실제 Matter 마커 위치와 현재 모드의 `AttachmentProbe`를 기준으로 주변 `SurfaceEdge`를 인식한다.
2. 방향 입력이 있으면 입력 벡터를 각 후보 접면의 접선에 투영하고, 임계값 이상으로 가장 잘 맞는 접면을 선택한다.
3. 방향 입력으로 선택된 접면이 없으면 현재 붙어 있는 edge를 유지한다.
4. 90도 모서리처럼 현재 접면과 다음 접면이 함께 인식될 수 있는 구간에서는 선택된 edge를 짧게 유지해 `selected`가 프레임마다 흔들리지 않게 한다.
5. 후보가 1-2프레임 비어도 직전 접면을 짧게 유지해 모서리 전환 중 `selected`가 순간적으로 `none`이 되지 않게 한다.
6. 유지할 현재 edge도 없으면 중력 반대 방향으로 달팽이를 받치는 접면을 선택한다.
7. 선택된 접면 방향으로 달팽이 물리 바디를 먼저 회전한 뒤 `snapPosition`으로 스냅하고, 해당 접선 방향 속도로 이동한다.

달팽이 이동 로직에는 오브젝트 타입별 예외를 추가하지 않는다. 특정 오브젝트가 다르게 동작해야 하면 `TemporaryPlayfield`에서 공통 `SurfaceEdge`나 별도 기믹 effect 데이터로 변환한 뒤 달팽이는 동일한 접면 규칙만 사용한다.

껍질 상태는 벽에 붙지 않고, 바닥이나 경사처럼 달팽이를 받치는 지지면만 접지와 경사 가속에 사용한다.

### 내부 진입 방어

`solid-to-bottom` 지형은 화면에서 흰색으로 채워진 전체 영역이 실제 충돌 영역이다. 달팽이는 해당 채움 영역 내부로 들어가면 안 된다.

이를 위해 `TemporaryPlayfield`는 `solid-to-bottom` 지형을 그려진 폴리곤과 같은 범위의 정적 충돌 바디로 채운다. 윗면은 기존 얇은 발판 바디로 유지하고, 윗면 아래부터 바닥까지는 좁은 세로 정적 바디들로 빈틈 없이 채운다.

접면 후보 판정도 내부 진입을 방어해야 한다. 달팽이 위치가 edge normal의 반대편, 즉 오브젝트 내부 방향에 있으면 해당 edge는 접면 후보로 인정하지 않는다. 스냅은 항상 edge normal 바깥쪽으로만 발생해야 한다.

접면 끝점에서 떨어진 다른 오브젝트로 순간 이동하는 것도 금지한다. 후보 접면의 `snapPosition`까지 이동해야 하는 거리가 접촉 허용 오차를 넘으면 해당 edge는 후보로 인정하지 않는다. 입력 방향이 맞더라도 실제 접촉 범위 밖의 접면으로는 전환하지 않는다.

접면 끝점 바로 근처는 정상적인 모서리 전환 후보로 유지한다. 끝점 근처 후보를 통째로 제거하면 90도 전환 지점에서 다음 접면을 인식하지 못하므로, 내부 진입 방어는 후보 제거가 아니라 normal 바깥쪽 판정, 스냅 거리 판정, 선택 edge 유지 시간으로 처리한다.

## 상태 관리

현재 일반 상태와 껍질 상태는 `SnailPlayer` 내부의 임시 상태값으로 관리한다. 후속 작업에서는 `src/states` 아래의 순수 상태 머신으로 먼저 정의한다. Phaser Scene은 상태 머신 결과를 읽어 물리 바디와 애니메이션에 반영하는 방향을 우선한다.

## 물리 엔진

Matter Physics는 Phaser 통합 기능을 사용한다. Matter.js를 별도 패키지로 설치하지 않는다.

현재 설정의 중력과 디버그 표시는 실행 확인용 임시값이며 최종 게임 규칙이 아니다.
