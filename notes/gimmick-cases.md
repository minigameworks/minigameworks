# 기믹 케이스 관리

## 목적

기믹 케이스는 특정 구조물 패턴이나 물리 동작을 메인 수직 맵까지 이동하지 않고 바로 검증하기 위한 작은 플레이어블 레벨이다.

신규 기믹은 먼저 이 문서에 등록하고, `src/systems/LevelDefinitions.ts`에 케이스 레벨을 추가한 뒤 `/?case=케이스키`로 실행해 검증한다. 검증이 끝난 케이스만 메인 수직 맵 상단 구간에 붙인다.

Scene은 여러 기믹 오브젝트로 이루어진 기믹 필드다. 오브젝트 하나가 단일 기믹이며, 필드, 수평 발판, 경사면 같은 기초 오브젝트도 모두 추적 대상이다.

## 관리 규칙

- 케이스 키는 영문 소문자와 하이픈을 사용한다.
- 케이스는 하나의 기믹 또는 하나의 구조물 패턴 검증에 집중한다.
- 검증 전에는 메인 수직 맵에 바로 붙이지 않는다.
- 검증 완료 후 메인 맵에 붙이면 `메인 맵 반영` 상태를 갱신한다.
- 실패하거나 보류한 케이스는 삭제하지 않고 이유를 남긴다.

## 상태 값

- `계획`: 아직 코드에 추가하지 않은 케이스
- `구현`: 케이스 씬에서 실행 가능한 상태
- `검증 중`: 실제 플레이 감각과 버그를 확인하는 상태
- `검증 완료`: 메인 맵에 붙일 수 있는 상태
- `반영 완료`: 메인 수직 맵에 붙인 상태
- `보류`: 현재 방향으로 사용하지 않기로 한 상태

## 기초 오브젝트 목록

| 오브젝트 종류 | 설명                                     | 현재 상태 | 관련 코드             |
| ------------- | ---------------------------------------- | --------- | --------------------- |
| `field`       | 수직 플레이 공간, 좌우 벽, 하단 바닥     | 구현      | `LevelDefinitions.ts` |
| `surface`     | 수평, 수직, 경사 여부와 무관한 표면 지형 | 구현      | `LevelDefinitions.ts` |

`surface`는 `fillMode`로 얇은 발판과 하단까지 채워진 지형을 구분한다. 수평면과 경사면은 별도 오브젝트 타입이 아니라 `SurfaceEdge`의 법선과 접선 벡터로만 구분한다. 현재 하단 채움 지형은 기초 구조물 검증용 표현이며, 최종 레벨 제작 단계에서는 지형 데이터와 기믹 데이터를 더 명확히 분리한다.

달팽이 일반 모드의 이동 판정은 오브젝트 종류가 아니라 `SurfaceEdge` 기준으로 처리한다. 각 오브젝트는 렌더링과 물리 바디 생성을 위한 데이터이며, 실제 부착과 이동은 오브젝트에서 변환된 edge의 법선, 접선, 진행도를 사용한다.

## 오브젝트 배치 규칙

- 오브젝트는 서로 다른 `id`를 가져야 한다.
- `field`는 레벨당 하나만 둔다.
- `surface`의 윗면, 옆면, 경사면은 일반 발판과 솔리드 지형 모두 같은 접면 규칙을 사용해야 한다.
- 새 지형 오브젝트는 반드시 공통 `SurfaceEdge`로 변환되어야 하며, 달팽이 로직에 오브젝트 타입별 예외를 추가하지 않는다.
- 달팽이 이동 로직에서 `surface`, `solid-to-bottom` 같은 오브젝트 타입을 직접 분기하는 코드는 금지한다.
- 미끄럼 표면은 오브젝트 타입이 아니라 `material`과 `surfaceSections`로 표현한다.
- 미끄럼 구간은 기존 `SurfaceEdge`를 분할하지 않고 edge 위의 진행도 기준으로 판정한다.
- 벽이나 기존 지형 위에 덧대는 미끄럼 필드는 별도 물리 body를 만들지 않고 기존 접면의 material section으로만 반영한다.
- 일반 모드는 `slippery` material 접면에 부착하지 않는다. 이미 붙어서 이동하다가 미끄럼 구간에 들어오면 접착이 풀리고 중력 방향으로 떨어진다.
- 접면 선택은 먼저 주변 접면 후보를 인식한 뒤, 입력 벡터가 후보 접면의 접선에 투영되는 정도를 기준으로 판단한다.
- 90도 모서리에서는 후보 접면이 동시에 잡힐 수 있으므로 선택된 edge를 짧게 유지해 `selected`가 프레임마다 바뀌거나 `none`으로 떨어지지 않게 한다.
- 서로 이어지지 않은 오브젝트가 가까이 있더라도 `snapPosition`까지 이동해야 하는 거리가 접촉 허용 오차를 넘으면 다음 접면으로 전환되지 않아야 한다.
- `solid-to-bottom` 지형은 하단 채움 표현과 실제 충돌 영역을 함께 추가하고, 윗면의 접면 판정은 얇은 발판과 같은 기준을 사용한다.
- `solid-to-bottom` 지형의 흰색 채움 영역은 전부 실제 충돌 영역이다. 달팽이는 해당 영역 내부로 들어가면 안 된다.
- 접면 후보는 edge normal 바깥쪽에서만 인식한다. normal 반대편 내부 위치는 스냅 후보로 인정하지 않는다.
- 접면 끝점에서 떨어진 위치는 스냅 후보로 인정하지 않는다. `snapPosition`까지 이동해야 하는 거리가 접촉 허용 오차보다 크면 입력 방향이 맞아도 전환하지 않는다.
- 접면 끝점 바로 근처는 정상적인 모서리 전환 후보로 남긴다. 끝점 후보 전체를 제거하는 방식은 다음 접면 인식을 막을 수 있으므로 사용하지 않는다.
- `solid-to-bottom` 지형의 좌우 옆면은 수직 접면으로 처리한다.
- `solid-to-bottom` 지형은 좌우 벽 바디와 겹치지 않게 배치한다. 벽에 붙는 구조가 필요하면 벽 안쪽 경계에 맞춰 시작점을 둔다.
- 발판 끝과 솔리드 지형 옆면을 연결할 때는 물리 바디가 겹치지 않게 끝점만 맞춘다. 겹치는 배치는 달팽이가 모서리에 끼거나 지형 안으로 파고드는 원인이 된다.
- 경사면의 윗면과 다른 오브젝트의 윗면이 1개 달팽이 반지름보다 가깝게 겹치지 않게 한다.
- 바닥에서 벽, 벽에서 경사면처럼 90도 접면 전환을 검증해야 하는 배치는 반드시 케이스 씬에서 먼저 확인한다.
- 새 오브젝트 배치는 `notes/gimmick-cases.md`의 케이스 목록과 체크리스트에 실행 주소와 검증 상태를 남긴다.

## `slope-transfer`

### 목표

경사 발판, 벽 부착 발판, 반대 방향 경사 발판을 짧은 구간에서 배치해 다음 동작을 확인한다.

- 일반 상태의 접면 부착과 접면 전환
- 껍질 상태의 경사면 이동
- 낮은 점프 후 구조물에 다시 붙는 흐름

### 실행

```text
http://localhost:5173/?case=slope-transfer
```

### 체크리스트

- [x] 케이스 레벨 정의가 있다.
- [x] URL 쿼리로 케이스 씬을 바로 실행할 수 있다.
- [ ] 일반 상태에서 경사면을 자연스럽게 이동할 수 있다.
- [ ] 껍질 상태에서 경사 방향 이동을 확인했다.
- [ ] 점프 후 다음 구조물에 붙는 흐름을 확인했다.
- [ ] 메인 수직 맵 상단 구간에 반영했다.

### 메모

현재는 세로 맵 확장 구조와 케이스 씬 실행 흐름 검증용이다. 최종 기믹 밸런스와 구조물 배치는 아직 확정하지 않는다.

## `pillar-gap`

### 목표

하단까지 채워진 기둥, 끊긴 이동 구간, 회수용 발판을 짧은 케이스 안에 배치해 다음 동작을 확인한다.

- 일반 상태의 기둥 옆면 부착과 안전한 등반
- 끊긴 구간에서 느린 이동과 빠른 껍질 이동의 위험도 차이
- 껍질 상태로 빠르게 넘을 때 발생하는 낙하 위험

### 실행

```text
http://localhost:5173/?case=pillar-gap
```

### 체크리스트

- [x] 케이스 레벨 정의가 있다.
- [x] URL 쿼리로 케이스 씬을 바로 실행할 수 있다.
- [x] 하단까지 채워진 기둥 오브젝트가 있다.
- [x] 끊긴 발판과 낙하 위험 구간이 있다.
- [ ] 일반 상태로 안전하게 기둥을 오를 수 있다.
- [ ] 껍질 상태로 빠르게 넘을 수 있지만 실패 시 낙하 위험이 있다.
- [ ] 메인 수직 맵 상단 구간에 반영했다.

### 메모

현재 배치는 기둥과 낭떠러지 패턴 검증용 값이다. 최종 기둥 높이, 간격, 낙하 리스크는 별도 레벨 디자인 단계에서 조정한다.

## `slippery-slope`

### 목표

좌우 벽면 미끄럼 필드와 중앙 `ㄱ`자 오버행의 좁은 미끄럼 구간을 배치해 다음 동작을 확인한다.

- 일반 상태는 미끄럼 구간에 부착하지 못한다.
- 일반 상태로 벽을 따라 이동하다 미끄럼 필드를 만나면 접착이 풀리고 중력 방향으로 떨어진다.
- 일반 상태로 중앙 `ㄱ`자 구조의 거꾸로 붙는 면을 이동하다 가운데 미끄럼 구간을 만나면 접착이 풀린다.
- 미끄럼 material은 기존 접면 edge를 쪼개지 않고 진행도 기준으로만 판정한다.
- HUD는 케이스 씬에서도 선택/인식 접면의 material을 표시한다.

### 실행

```text
http://localhost:5173/?case=slippery-slope
```

### 체크리스트

- [x] 케이스 레벨 정의가 있다.
- [x] URL 쿼리로 케이스 씬을 바로 실행할 수 있다.
- [x] 좌우 벽면 미끄럼 필드가 있다.
- [x] 중앙 `ㄱ`자 오버행의 가운데 좁은 미끄럼 구간이 있다.
- [x] 미끄럼 표면이 기존 top edge를 분할하지 않는다.
- [ ] 일반 상태가 미끄럼 구간에 부착하지 않는지 확인했다.
- [ ] 일반 상태가 미끄럼 구간에서 중력 방향으로 떨어지는지 확인했다.
- [ ] 메인 수직 맵 상단 구간에 반영했다.

### 메모

현재 미끄럼 필드 길이와 위치는 기믹 검증용 값이다. 최종 배치 밀도와 시각 표현은 별도 튜닝 단계에서 결정한다.
